# Uninitialised reads proven benign, for the power-on fill
# (OT6_POWERON_FILL, lib/poweron_fill.lua) and the read-before-write
# instrument (OT6_RBW, tools/rbw_report.py).  docs/TOOLING.md "Uninitialised
# memory".
#
#   fill <region> <lo>[-<hi>] <reason>
#       the fill leaves these offsets zero, so a read already understood
#       does not move the play and hide what comes after it.  Each one names
#       the instruction, what the value changes, and the evidence.
#   read <file>:<line> <ram> <reason>
#       tools/rbw_report.py counts this instruction's reads of unwritten
#       bytes without listing them.
#
# A waiver is a finding, not a fix: each says why it is harmless, or why it
# is left for the ROM's owner (the proposed fix is in the reason).

fill wram 1F6E-1F6F the random-battle counter: vanilla adds each step to it (field/battle.asm:168, Ot6DangerStep's `adc a:$1f6e`, ot6_break.asm:485) and clears it only after a battle, and New Game never zeroes it, so the first random encounter after a New Game comes after a power-on-dependent number of steps (vanilla; on a Continue the slot's value loads). Fix: zero it in Ot6NewGameClear. build/attempts/wt/v046-fills/regions/gen_whelk_poweron_ones_wram_1F6E-1F6F.log
fill wram E9DB the condemned-numeral counter (btlgfx_main.asm:41571 UpdateCondemnNum, `lda w7ee9db / and #$03`): its low bits pick which frame of four redraws a numeral, so its first value only moves which frames carry the redraw; that shifts the frame a later field event lands on (vanilla, cosmetic in origin; the first battle after power-on reads it unwritten). Fix: zero it where battle graphics init clears its block. build/attempts/wt/v046-fills/regions/gen_whelk_poweron_ones_wram_E9DB.log
fill wram EDCE OT6_PASSRETARGET, an OT6 BUG: Ot6PassRetarget (ot6_passes.asm:159) reads it when ChooseTarget retargets, and its only clear is InitGfxScript's at the start of each action (battle_main.asm:6501), so a retarget before the first action of a battle after power-on reads it unwritten (and one in any later battle reads the previous battle's last mark); with bit 7 set it takes OT6's pass rule instead of vanilla's Retarget, and a Fight lands on another body. Fix: zero it at battle start beside OT6_BLUESEEN (ot6_boost.asm:52). Left zero here so the line can be compared past it. build/attempts/wt/v046-fills/kolts/b3/EDCE.log
